Quick Sort, step by step

      Best, worst, expected

      If every pivot lands near the middle, the tree has about log₂ n levels and each level costs Θ(n): Θ(n log n). If every pivot is the smallest or largest key (sorted input with a fixed last or first pivot), each call removes only one key: T(n) = T(n−1) + Θ(n) = Θ(n²) and the recursion is n levels deep. A random pivot makes the expected cost about 1.39 n log₂ n comparisons on every input.

      Lomuto or Hoare?

      Lomuto is easier to prove and puts the pivot in its final place, but with many equal keys it sends them all to one side. Hoare does about three times fewer swaps and splits equal keys evenly, but the pivot is not fixed in place, so it recurses on A[p..q] and A[q+1..r]. Neither is stable. Quickselect recurses into one side only: Θ(n) expected.
