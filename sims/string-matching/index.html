String matching, step by step

Find every place where a pattern P of length m occurs in a text T of length n. The naive method tries every shift and can make about n·m comparisons. The others use what they already know about P to skip shifts that cannot match: a hash (Rabin–Karp), an automaton, the prefix function (KMP), a bad-character table (Boyer–Moore) or Z-boxes.

    Why KMP never moves back

    When q characters have matched and the next one fails, we already know the last q text characters: they are P[0..q−1]. The longest proper prefix of P that is also a suffix of them, π[q − 1], tells us the next shift that could possibly work, and that its first π[q − 1] characters already match. So the text pointer i only moves forward: at most 2n comparisons.

    Spurious hits

    Rabin–Karp compares numbers mod q. Different windows can have the same value mod q, so every hit must be checked character by character. Try the Digits example: 67399 ≡ 7 ≡ 31415 (mod 13) is a spurious hit. A large prime q makes them rare; the expected time is O(n + m).

    Why Boyer–Moore is fast

    It compares from the right end of the pattern. If the text character there does not occur in P at all, the pattern can jump m places at once. On ordinary text with a large alphabet it usually inspects only a fraction of the characters; this is why text editors use it.
