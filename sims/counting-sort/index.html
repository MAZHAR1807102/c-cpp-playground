Counting Sort, step by step

Count each key, turn the counts into prefix sums, then place every key from right to left. Equal keys carry a letter (3a, 3b, 3c) so you can watch them keep their order.

Pseudocode

  1. let C[0..k] be a new array of zeros
  2. for j ← 1 to n
  3. C[A[j]] ← C[A[j]] + 1
  4. for v ← 1 to k
  5. C[v] ← C[v] + C[v−1]
  7. B[C[A[j]]] ← A[j]
  8. C[A[j]] ← C[A[j]] − 1

Why right to left?

After prefix sums, C[v] is the last slot reserved for value v. Scanning from the right puts the last copy of v in the last slot, the copy before it one slot earlier, and so on. Equal keys keep their input order, so the sort is stable. Switch the scan to left to right and run again: the equal keys come out reversed.

Cost

Loop 1 runs n times, loop 2 runs k times, loop 3 runs n times, so time is Θ(n + k), and C plus B need Θ(n + k) extra memory. No two keys are ever compared. It is linear only when k = O(n).
