      Why Θ(n log n)?

      T(n) = 2T(n/2) + Θ(n). The call tree has ⌈log₂ n⌉ levels below the root, and the merges on one level together write each of the n keys once. So the total work is Θ(n log n) in the best, average and worst case. Merge needs L and R, so the extra memory is Θ(n).

      Stable, and it counts inversions

      On a tie the merge takes from L first, so equal keys keep their order: merge sort is stable. When R[j] is taken while L still holds |L| − i + 1 keys, R[j] is smaller than all of them, so add that many inversions. Summed over all merges this gives the inversion count in Θ(n log n).
