Shortest paths, step by step

Find the least-weight path between vertices of a weighted, directed graph. Every algorithm here is built on one operation, relaxation: if going through u gives v a shorter path, take it. They differ in the order they relax edges, and that decides what they can handle: negative edges, negative cycles, one source or all pairs.

      Relaxation

      Each vertex keeps v.d, the best distance found so far (an upper bound), and v.π, its predecessor. RELAX(u, v) asks: is u.d + w(u, v) smaller than v.d? If so, v gets the shorter path through u. Distances only ever go down, and once v.d equals the true distance δ(s, v) it never changes again.

      Why Dijkstra needs w ≥ 0

      Dijkstra finalises a vertex as soon as it is extracted, trusting that no later path can be shorter, since every later path only adds non-negative weights. One negative edge breaks this. Open Dijkstra fails: a is finalised with d = 2, then b → a (−2) lowers it to 1, but c has already used the old value and keeps 3 instead of 2.

      Negative cycles

      If a cycle has negative total weight, going round it again always makes a path shorter, so “shortest path” has no answer for any vertex reachable through it. Bellman–Ford spots it because an edge can still be relaxed after V − 1 passes; Floyd–Warshall because a diagonal entry becomes negative.

      Which one to use?

      Unweighted: BFS. Non-negative weights: Dijkstra. Negative edges: Bellman–Ford, or the faster DAG method if there are no cycles. All pairs: Floyd–Warshall for dense graphs (short code, Θ(V³)), Johnson for sparse graphs.
